# ADR-025

Date
2026-08-03

Track
Track B (Dry Research)

## Question

ADR-018では特徴量抽出モジュールを独立化し、各モジュールが個別に特徴量を生成する構成を採用した。現在、FeatureDSSP、FeaturePISA、FeatureContactおよびADR-023で定義したEdgeFeaturesの実装が進んでいる。 【1-addd74】【2-876be5】

一方で、Dataset A構築に向けては多数のPDBについて同一処理を繰り返し実行する必要がある。

現在は各モジュールを個別実行する運用であるが、

- データセット一覧から一括実行したい
- Node FeatureだけでなくEdgeおよびEdge Featureも同時に生成したい
- 既に計算済みの処理は自動的にskipしたい
- 各Featureモジュールの独立性は維持したい

という要求が生じている。

特徴量生成パイプラインをどのようにバッチ実行するか。

## Decision

PDB_analysis直下に DatasetPreparation ディレクトリを新設する。

DatasetPreparationは各Featureモジュールを統括するオーケストレーション層として位置付ける。

計算結果は各モジュールが従来通り自身の results_* ディレクトリへ出力する。

DatasetPreparation自身は特徴量データを保持しない。

## Architecture

```text
PDB_analysis/

├── DatasetPreparation/
│
│   ├── run_dataset_preparation.py
│   ├── modules.yaml
│   ├── logs/
│   └── reports/
│
├── FeaturesDSSP/
├── FeaturesPISA/
├── FeatureContact/
├── Edge/
├── EdgeFeatures/
├── FeatureExtraction_Overview/
└── PDB-VLP-list/
```

DatasetPreparationは各モジュールを実行するのみとし、モジュール内部の処理内容には介入しない。

## Input Dataset

DatasetPreparationはPDB一覧CSVを入力として受け取る。

初期対象は

```text
PDB-VLP-list/results/gold_T1-enc.csv
```

とする。 【1-45127a】

処理対象PDBは

```text
pdb_id
```

列から取得する。 【1-45127a】

例

```text
3DKT
6I9G
7S21
9B9I
```【1-45127a】

## Execution Order

DatasetPreparationは以下の順序で実行する。

```text
FeatureDSSP
      ↓
FeaturePISA
      ↓
FeatureContact
      ↓
Edge
      ↓
EdgeFeatures
```

Node FeatureとEdge Featureを分離したバッチ処理は採用しない。

利用者は単一コマンドによってGraph構築に必要な全特徴量を生成する。

## Dependency Management

EdgeFeaturesはEdgeに依存する。

```text
Edge
  ↓
EdgeFeatures
```

Edgeが未生成の場合はEdgeFeaturesを実行しない。

Node Featureモジュール同士には依存関係を持たせない。

## Output Policy

各モジュールは従来通り自身のディレクトリへ結果を保存する。

例

```text
FeaturesDSSP/results_3DKT/
FeaturesPISA/results_3DKT/
FeatureContact/results_3DKT/
Edge/results_3DKT/
EdgeFeatures/results_3DKT/
```

DatasetPreparationは成果物をコピーしない。

成果物の正本は各モジュールが保持する。

## Skip Policy

再計算不要なモジュールは自動的にskipする。

skip判定には done.flag を利用する。

例

```text
FeaturesDSSP/results_3DKT/

    feature.csv
    plots/
    summary.json
    done.flag
```

正常終了時にdone.flagを生成する。

DatasetPreparationはdone.flagの存在を確認し、

```text
done.flagあり
    → skip

done.flagなし
    → execute
```

とする。

## Force Recalculation

全モジュール再計算のために

```text
--force
```

オプションを提供する。

```bash
python run_dataset_preparation.py \
    gold_T1-enc.csv \
    --force
```

指定時はskip判定を無効化する。

## Module Selection

開発時の部分実行を可能とする。

```text
--module
```

オプションを提供する。

例

```bash
python run_dataset_preparation.py \
    gold_T1-enc.csv \
    --module EdgeFeatures
```

指定されたモジュールのみ実行する。

## Batch Report

実行履歴を保存する。

例

```csv
pdb_id,module,status
3DKT,DSSP,success
3DKT,PISA,success
3DKT,Contact,skip
3DKT,Edge,success
3DKT,EdgeFeatures,success
```

レポートは

```text
DatasetPreparation/reports/
```

へ保存する。

## Relationship with ADR-024

ADR-024ではFeature GenerationとMergeFeaturesの間にFeature Review工程を導入した。 【1-addd74】【2-876be5】

本ADRはそのうちFeature Generation部分を自動化するものである。

パイプライン全体は以下のように構成する。

```text
DatasetPreparation
        ↓
Feature Review Gallery
        ↓
Feature Selection
        ↓
MergeFeatures
        ↓
Graph Dataset
```

Feature Review Galleryは既存のFeatureExtraction_Overviewを利用する。 【1-e732e1】

## Rationale

Dataset Aは数十から200構造程度を対象としており、同一Featureパイプラインを反復実行する運用が想定される。 【1-addd74】【1-45127a】

Feature、Edge、EdgeFeaturesを個別管理すると運用負荷が増大する。

一方で、各モジュール自体は独立性を維持することが望ましい。

そこで、

- Feature生成は一括実行
- Feature保存は各モジュール
- Reviewは独立
- Mergeも独立

という構成を採用する。

これによりADR-018の独立モジュール思想を維持しながら運用を自動化できる。 【1-addd74】

## Alternatives Considered

### Alternative 1

各モジュールを個別実行し続ける。

**Rejected**

PDB数増加に伴い運用負荷が高い。

### Alternative 2

Node FeatureとEdge Featureを別バッチにする。

**Rejected**

利用者視点ではGraph構築のための特徴量生成であり、分離する利点が小さい。

### Alternative 3

Feature・Edge・EdgeFeaturesを単一DatasetPreparationで実行する。

**Accepted**

運用が最も単純であり、Graph Dataset生成の流れに適している。

## Consequences

### Positive

- データセット単位で一括実行できる
- Node FeatureとEdge Featureを統一的に管理できる
- 自動skipにより再計算を削減できる
- モジュール独立性を維持できる
- ADR-024のFeature Review工程と自然に接続できる
- MergeFeatures実装前段として利用できる

### Negative

- DatasetPreparationという管理レイヤーが追加される
- done.flag管理が必要になる
- モジュール間インターフェースの維持が必要になる
