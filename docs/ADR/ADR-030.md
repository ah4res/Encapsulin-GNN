# ADR-030
# Research Group Classification for Feature Registry

Date: 2026-08-04

## Status

Accepted

## Context

Feature Registryの拡張に伴い、登録される特徴量数が増加している。

特徴量は同じ役割を持つわけではなく、

- 既知の重要因子
- 正二十面体対称性因子
- 新規探索因子

が混在する状態になりつつある。

また、GPS Landscape-based Feature Ablation Frameworkでは、

Feature Setの体系的な比較が必要となる。

従来の

- source
- type
- dtype

のみでは、

研究上の役割を管理できない。

Feature Registryを単なる実装設定ファイルではなく、

研究仮説管理台帳

として利用する必要がある。

## Decision

Feature Registryへ

research_group

カラムを追加する。

定義は以下とする。

### Group A

Positive Control Features

既知の重要因子。

解析系が正常に動作しているか確認するための特徴量群。

代表例

- interface_flag
- interface_degree
- total_interface_area
- global_dasa
- total_n_2A
- total_n_4A
- total_n_6A
- total_n_8A
- total_n_10A

期待される結果

高GPS残基が界面へ局在する。

研究的新規性の評価対象ではなく、

解析系の妥当性確認を目的とする。

### Group B

Symmetry Features

正二十面体対称粒子特有の対称性情報。

候補

- dist_to_5fold
- dist_to_3fold
- dist_to_2fold
- radius_from_center
- symmetry_contact_count
- symmetry_relation

期待される結果

GPS Landscapeが

- 5回軸
- 3回軸
- 2回軸

周辺へ局在する。

本研究の主要仮説群として扱う。

### Group C

Discovery Features

重要性が未知であり、

新しい粒子形成原理探索を目的とする特徴量群。

候補

- strain
- curvature
- delta_curvature
- packing_density
- local_roughness
- symmetry_deviation
- contact_frustration

期待される結果

既存知識では説明できないLandscapeを生み出す。

新規発見候補として扱う。

## Single Source of Truth

research_group の定義は

feature_registry.yaml

のみで管理する。

他の設定ファイル、

Pythonコード、

Notebook、

ドキュメントにおいて

research_group を重複定義してはならない。

GraphBuilderは

feature_registry.yaml

を唯一の参照元

(Single Source of Truth)

として利用する。

将来的に

Group A

Group B

Group C

の定義が変更された場合も、

feature_registry.yaml

のみを修正する。

全てのFeature Set生成、

Feature Ablation実験、

GPS Landscape解析は、

feature_registry.yaml

に定義された

research_group

を参照して実施する。

研究上のFeature分類は、

ADR本文ではなく

feature_registry.yaml

を正本とする。

ADRは分類ルールを定義するが、

具体的なFeatureの所属先は

feature_registry.yaml

のみが正本である。

## Baseline Definition

Feature Ablation実験におけるBaselineは

PLM + Interface

とする。

理由

PLM単独ではAssembly情報が不足する可能性がある。

Interface情報は既知かつ生物学的妥当性が高く、

最も現実的な比較対象となる。

基本比較形

Baseline

PLM
+
Interface

↓

Baseline + Symmetry

PLM
+
Interface
+
Symmetry

↓

Baseline + Symmetry + Discovery

PLM
+
Interface
+
Symmetry
+
Strain

など。

## Consequences

利点

- Feature設計の研究的役割を明示できる
- Group単位でFeature Setを構築可能
- GPS Landscape-based Feature Ablationが体系化される
- Positive ControlとDiscoveryを区別できる
- Feature Registryを研究仮説管理台帳として利用できる
- Feature分類の正本を一箇所へ集約できる

欠点

- Feature登録時の管理負荷が増える
- Discovery Groupの定義が将来変化する可能性がある
- feature_registry.yamlの管理品質が重要になる

## Notes

本ADRは特徴量そのものの採否を決定するものではない。

本ADRは特徴量の研究上の役割を管理する分類体系を定義するものである。

今後のFeature Ablation実験は、

Group A
↓

Group B
↓

Group C

の順に段階的に評価する。

feature_registry.yaml は

Featureに関する唯一の正本

(Single Source of Truth)

として扱う。
