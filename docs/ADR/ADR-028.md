#### ADR-028

Date

2026-08-07

Track

Track B

Question

GraphBuilderが出力するGraph Directory（Graph-001, Graph-002, ...）を、
Graph Neural Network学習で利用可能なPyTorch Geometric形式へ
どのように変換し、追跡可能性を維持するか。

Decision

PyTorch Geometric Export（PyG-Export）を独立モジュールとして実装する。

PyG-Exportの入力単位は

Graph Directory

とする。

入力例

```text
Graph-001/
Graph-002/
Graph-006/
```

PyG-ExportはGraph Directory内の

```text
graph_manifest.json
experiment_manifest.json
merged_node_features.csv
merged_edge_features.csv
```

を参照する。

PyG-Exportは
CSVファイル単位ではなく、
Graph Directory単位で処理を行う。

出力形式は

```text
Graph-001_pyg.pt
Graph-002_pyg.pt
Graph-006_pyg.pt
```

とする。

PyTorch Geometricの内部形式は

```python
Data(
    x,
    edge_index,
    edge_attr
)
```

とする。

特徴量追加時に
PyG-Exportコードの修正が不要となるよう、
特徴量列は固定定義しない。

特徴量は

feature_registry.yaml

および

graph_manifest.json

から自動取得する。

node_idと残基番号の対応関係を保持するため、

```text
Graph-001_node_mapping.csv
```

を生成する。

node_mappingは最低限、

```text
node_id
residue_index
```

を保持する。

PyG-Exportは以下のValidationを実行する。

- node数整合性
- edge数整合性
- edge_index範囲確認
- 欠損値確認
- 孤立ノード確認

Validation結果は

```text
Graph-001_pyg_manifest.json
```

に保存する。

---

Rationale

GraphBuilderは

Graph構築

までを責務とする。

PyTorch Geometric形式への変換は
別モジュールで実施する。

GraphBuilderとPyG-Exportの責務を分離することで、

- GraphBuilder
- PyG-Export
- GraphMAE
- GraphCL

を独立して保守可能とする。

本プロジェクトでは、

特徴量モジュール

↓

GraphBuilder

↓

PyG

↓

Encoder

↓

GPS Landscape

の追跡可能性が重要である。

GraphBuilderは既に

```text
Graph-XXX/

graph_manifest.json

experiment_manifest.json
```

によって

- Feature Set
- Dataset
- 実験ID
- Graph ID

を保持している。

そのため、

PyG-Exportでは独自のFeature Set IDを導入せず、

Graph ID

を唯一の追跡キーとして利用する。

---

Alternatives Considered

Alternative 1

CSVファイルを直接入力として扱う。

例

```text
merged_node_features.csv
merged_edge_features.csv
```

不採用。

理由

GraphBuilderが保持している

- Experiment
- Feature Set
- Dataset

情報が失われる。

Graph単位の追跡性が低下する。

---

Alternative 2

GraphBuilder出力ディレクトリ内に
PyGファイルを保存する。

例

```text
Graph-006/

Graph-006_pyg.pt
```

不採用。

理由

GraphBuilderとPyG-Exportの責務分離を維持したい。

モジュール横断を避ける。

---

Alternative 3

Feature Set ID（FS-XXX）を
PyGレベルで独立管理する。

不採用。

理由

graph_manifest.json

および

experiment_manifest.json

内にFeature Set情報が既に保持されている。

Graph IDから完全に追跡可能であり、
重複管理となる。

```text

```

とする。

Graph-006

標準変換層を定義する。
