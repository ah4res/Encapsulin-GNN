# ADR-027

Date
2026-08-03

Track
Track B (Dry Research)

## Question

GraphBuilderは特徴量を統合しGraph Datasetを構築する基盤として設計している。今後、Protein Language Model (PLM) を利用した特徴量の導入を予定している。

候補としては以下が想定される。

```text
ESM2
ESM-C
ProtT5
ankh
ProstT5
```

PLMはモデルサイズが大きく、ダウンロード・管理・更新・切り替えが必要となる。

一方でGraphBuilderおよび特徴量生成モジュール側から見ると、

```text
PDB ID
↓
PLM特徴量
```

が取得できれば十分であり、どのモデルを利用しているかは本来隠蔽されるべきである。

PLM管理とPLM特徴量生成をどのように設計するか。

## Decision

PLM機能は以下の二層構造で実装する。

```text
PrepPLM
↓
FeaturesPLM
```

### PrepPLM

責務

```text
PLMモデル管理
```

のみとする。

以下を管理対象とする。

- モデルダウンロード
- モデル保存
- tokenizer管理
- config管理
- モデル切り替え
- モデル更新

PrepPLMは特徴量生成を行わない。

### FeaturesPLM

責務

```text
PLM特徴量生成
```

のみとする。

入力

```text
PDB ID
```

出力

```text
plm_features.csv
```

FeaturesPLMはPrepPLMから利用可能なモデルを取得し、

```text
SEQRES
↓
PLM推論
↓
Embedding生成
```

を実施する。

## Architecture

構成を以下のように定義する。

```text
PDB_analysis/

├── PrepPLM/
│
│   ├── models/
│   │
│   ├── esm2/
│   ├── prott5/
│   ├── ankh/
│   └── ...
│
│   ├── download_model.py
│   ├── update_model.py
│   └── model_registry.yaml
│
├── FeaturesPLM/
│
│   ├── feature_plm.py
│   ├── feature_plm.ipynb
│   ├── results_<PDBID>/
│   └── README.md
```

## Separation of Responsibilities

PrepPLMは以下を知らない。

```text
PDB
SEQRES
GraphBuilder
Feature Review
```

PrepPLMは純粋なモデル管理モジュールとする。

FeaturesPLMは以下を知らない。

```text
モデル保存場所
ダウンロード方法
モデル更新方法
```

FeaturesPLMはPLM特徴量生成のみ担当する。

## GraphBuilder Integration

GraphBuilderから見えるPLM関連モジュールは

```text
FeaturesPLM
```

のみとする。

GraphBuilderはPrepPLMを直接参照しない。

GraphBuilderは既存モジュールと同様に扱う。

例

```text
FeaturesAA
FeaturesDSSP
FeaturesPISA
FeaturesContact
FeaturesPLM
EdgeFeatures
```

GraphBuilderはFeature Registryを通じて特徴量を取得する。
