# ADR-022

Date  
2026-08-03

Track  
Track B (Dry Research)

## Question

Encapsulin-GNNにおいて、missing residue（non-model region）をどのように表現するか。

現行実装ではFeaturesDSSPおよび他の特徴量抽出モジュールはATOMレコードのみを対象としており、座標を持たない残基は完全に消失している。

その結果、PDB構造中に存在するmissing residueがGNNグラフ上では表現されず、生物学的配列とGNNノード集合が一致しない問題が確認された。

## Decision

GNNノードはATOMレコードではなくSEQRES配列を基準として定義する。

すべてのFeature抽出モジュールはSEQRESベースへ移行する。

各残基についてSEQRES由来の全残基ノードを作成し、missing residueもノードとして保持する。

missing residueには以下の特徴量を付与する。

```text
is_missing
```

```text
0 = modeled residue
1 = missing residue
```

さらに各missing residueについて、

```text
missing_segment_length
```

を特徴量として保持する。

例

```text
59-70 missing

↓

12残基

↓

segment内の全残基に

missing_segment_length = 12
```

を付与する。

既存のFeaturesDSSP、FeatureContact、FeaturePISA等はSEQRESベースの残基番号にマッピングして出力する。

計算不能な特徴量については欠損値として保持する。

例

```text
RSA
secondary structure
dASA
contact count
```

など。

## Rationale

現在の実装では、

```text
SEQRES
↓
ATOM
↓
DSSP
↓
Feature Table
```

という流れになっており、missing residueが全て消失する。

実データ検証では、

```text
3DKT
missing 1 residue

7S21
missing 36 residues
(11.96%)

9B9I
missing 19 residues
(6.76%)
```

であり、構造によっては無視できない割合の残基が欠損していることが確認された。

特に7S21および9B9Iでは内部欠損領域が存在しており、missing residueを除去したままではタンパク質本来の配列長や残基位置情報が失われる。

またmissing residueは単なる欠測ではなく、

```text
高い柔軟性

未観測ループ

未観測ドメイン

構造的不均一性
```

を意味する生物学的情報である。

したがってmissing residueは削除せず、明示的な特徴量として保持する。

さらに、

```text
10残基程度の欠損ループ

100残基規模の欠損ドメイン
```

は生物学的意味が大きく異なる。

そのため、

```text
is_missing
```

だけでなく、

```text
missing_segment_length
```

を保持する。

## Alternatives Considered

### Alternative 1

現在の実装を維持する。

```text
Node = ATOM residue
```

**Rejected**

missing residueが完全に消失し、配列情報を保持できない。

---

### Alternative 2

missing residueを無視し、

```text
is_missing
```

も持たせない。

**Rejected**

7S21では約12％の残基が消失しており、解析上の影響が無視できない。

---

### Alternative 3

AlphaFold予測構造を生成し、

missing residueへ座標を与える。

**Deferred**

有望であるが、

- 計算コストが高い
- 実験構造と予測構造が混在する
- Dataset全体への適用が重い

ため現時点では採用しない。

将来的なADRで再検討する。

---

### Alternative 4

missing residueに対して

```text
is_missing
```

のみ保持する。

**Rejected**

短い欠損ループと長い欠損ドメインを区別できない。

## Consequences

今後すべての特徴量抽出モジュールは、

```text
Node = SEQRES residue
```

を前提として実装する。

Feature Merge時にはSEQRES残基番号を主キーとする。

missing residueについては、

```text
is_missing
missing_segment_length
```

を共通Node Featureとして保持する。

構造由来特徴量が計算不能な場合は欠損値として扱う。

## Validation Results

FeaturesDSSP検証により以下を確認した。

```text
3DKT

SEQRES            265
ATOM              264
DSSP              264
FeaturesDSSP      264

Missing             1
```

```text
7S21

SEQRES            301
ATOM              265
DSSP              265
FeaturesDSSP      265

Missing            36
```

```text
9B9I

SEQRES            281
ATOM              262
DSSP              262
FeaturesDSSP      262

Missing            19
```

また、

```text
ATOM = DSSP = FeaturesDSSP
```

であることから、

現在のFeaturesDSSPはmissing residueを保持していないことを確認した。

本ADRに基づき、今後のFeature抽出基盤をSEQRESベースへ移行する。
