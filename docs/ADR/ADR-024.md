# ADR-024

Date
2026-08-03

Track
Track B (Dry Research)

## Question

ADR-018では特徴量抽出を独立モジュール化し、MergeFeaturesによって統合する方針を採用した。現在、FeatureDSSP、FeaturePISA、FeatureContactに加え、ADR-023で定義したEdgeFeaturesの実装を進めている。 【1-08d007】【2-19c769】

MergeFeatures実装に先立ち、生成された特徴量をそのまま統合するのではなく、人間が特徴量および関連QC図を確認し、学習へ採用するかを判断する工程を正式に導入すべきか。

また、そのレビュー作業を支援する仕組みをどのように実装するか。

## Decision

Feature GenerationとMergeFeaturesの間に、Feature Review工程を正式に導入する。

Feature pipelineを以下のように定義する。

```text
Feature Generation
        ↓
Feature Review
        ↓
Feature Selection
        ↓
MergeFeatures
        ↓
Graph Dataset
```

特徴量の採用可否は、学習前に人間が確認し決定する。

Feature Reviewを支援するために、Feature Review Galleryを採用する。

Galleryは既存Featureモジュールが出力する成果物を再利用し、新規特徴量や新規plotは生成しない。

## Feature Review Gallery

### Purpose

Feature Review Galleryは特徴量の品質確認および採用判断を支援することを目的とする。

以下は本Galleryの対象外とする。

- 特徴量の自動選択
- 新規plot生成
- 統計解析
- 学習性能評価

### View 1: By PDB

PDB単位で全Featureモジュールの出力を横断参照する。

例

```text
3DKT
 ├ DSSP
 ├ PISA
 ├ Contact
 └ EdgeFeatures

7S21
 ├ DSSP
 ├ PISA
 ├ Contact
 └ EdgeFeatures
```

各モジュールが出力したplotをサムネイル形式で一覧表示する。

クリックすると原寸画像を表示する。

FeatureExtraction_Overviewで採用しているPDB横断参照の考え方を継承する。 【1-77f1bc】

### View 2: By Feature

特徴量単位でPDB間比較を可能とする。

例

```text
actual_distance
 ├ 3DKT
 ├ 7S21
 └ 9B9I

ss_pair
 ├ 3DKT
 ├ 7S21
 └ 9B9I

sasa
 ├ 3DKT
 ├ 7S21
 └ 9B9I
```

同一特徴量について複数PDBの出力を横断比較できるようにする。

特徴量一覧は各Featureモジュールが出力するCSVヘッダまたはfeature manifestから自動生成する。

### Presentation

GalleryはHTML形式とする。

最低限の機能は以下とする。

- plot一覧表示
- サムネイル表示
- クリックによる拡大表示
- By PDBビュー
- By Featureビュー

Galleryはレビュー支援ツールであり、加工済み統計値や新規可視化は生成しない。

既存モジュールが生成したplotのみを集約して表示する。

## Rationale

現在のDataset A規模は数十から200構造程度であり、人間による特徴量レビューを十分実施可能である。 【1-08d007】

特徴量は生成後に直ちにMergeするのではなく、

- 分布が妥当であるか
- 欠損値処理が想定通りであるか
- 構造生物学的解釈と矛盾しないか
- 学習に投入する価値があるか

を確認した上で採用判断を行う。

特にADR-023で定義したEdgeFeaturesである

- actual_distance
- sequence_distance
- ss_pair
- same_ss_element

については構造ごとの分布確認が重要である。 【2-19c769】

既存のFeatureExtraction_Overviewでは主としてPDB単位の横断参照を提供している。 【1-77f1bc】

しかし、今後はMergeFeaturesによる統合が予定されており、特徴量単位で横断的に評価する仕組みが必要となる。

そのため、

```text
PDBを見る
```

だけでなく、

```text
特徴量を比較する
```

という観点を正式に導入する。

Feature Review GalleryはFeature Selectionのためのレビュー基盤として位置付ける。

## Alternatives Considered

### Alternative 1

Feature生成後に直接MergeFeaturesへ投入する。

**Rejected**

特徴量の品質確認や採用判断の機会が失われる。

不要な特徴量や品質が不十分な特徴量が学習データへ混入する可能性がある。

### Alternative 2

MergeFeatures実行後にレビューする。

**Rejected**

不要な特徴量が統合済みデータへ混入する。

特徴量単体での評価が困難になる。

### Alternative 3

Feature Review工程を導入し、人間が確認後にMergeする。

**Accepted**

研究規模に対して現実的であり、特徴量の理解と品質向上に最も有効である。

## Consequences

### Positive

- 特徴量のブラックボックス化を防止できる
- MergeFeatures入力品質を向上できる
- Feature採用判断の根拠を記録できる
- 新規特徴量追加時にも同一レビュー手順を適用できる
- PDB単位および特徴量単位の両方で比較可能となる
- EdgeFeaturesを含む全特徴量を統一的に確認できる
- MergeFeaturesの責務を単純化できる

### Negative

- Merge前工程が追加される
- 完全自動パイプラインではなくなる
- Review結果の確認に人的コストが発生する
